# 雨庭书院 · The Raincourt

## 设计结论

从零开始，我会把主角从“一个漂亮的魔法信封”换成“第一次走进玛甘比的感受”。这不是一套换上学院徽记的报名表，而是一段由空间、器物与书写组成的入学仪式：雨后庭院先建立地方感，桌上的木匣建立人与学院的联系，薄纸把视觉注意力从场景转向文字，最终用一份能被真实收存的来信结束体验。

本方案定名为“雨庭书院”。它用热带林荫、开放式木构、低矮的石台、水面、旧铜与纸纤维，表达古老而仍然有人生活的学院。庄严来自时间与秩序，不来自宫殿尺度、昂贵材质的堆砌或强烈发光。它不采用哥特城堡、黑金奢华、玻璃卡片、霓虹符文，也不把学院简化成五个竞争的性格分院。

## 与《万千之力》的关系

Paizo 对这条冒险之路的介绍明确强调非西方魔法学院，以及学生逐渐成为教师、承担知识传承责任的经历。玩家指南的介绍也强调同届学生相互支持、共同学习。这使“抵达一个共同体”比“被某种神秘力量选中”更适合作为招募的情绪核心。[1][2]

五支学派分别强调想象、同伴与共同体、适应、勇气和知识。界面使用五种价值帮助理解学院，不把它们做成颜色鲜明的竞赛阵营，也没有用问卷结果给玩家强制分院。[3] 来信中关于同行、经历与传授知识的文字，是为本界面创作的邀请语，不是对某位官方人物台词的引用。

雨庭的具体建筑、场景坐标、五叶标记、木匣造型和植物图版都是本项目的原创表达。这里不是官方校园地图复刻，也没有声称“雨庭书院”是模组中已有的地点。项目没有捆绑官方插图，没有从其他现实文化中随意抽取宗教符号作为装饰。原工程的题目与材料保留原文，其设定正确性不等同于本次重新核验过全部原书。

## 视觉语言

主色不是泛用的“翡翠加金色”，而是分工明确的材料色。森林深色 `#102B25` 用于场景和阅读区的外部空间，温纸色 `#F0E8D6` 只承担书写和阅读，墨绿 `#203A31` 承担正文，旧铜 `#BFA879` 用于少量秩序标记，陶红 `#A94F37` 只承担启封与寄出等真正重要的行动。按钮不与背景争相发光，金属也不被用来给所有内容描边。

中文标题使用系统宋体类字体，以完整句子而不是密集标签建立节奏；说明、表单与工具使用系统无衬线字体；英文小字只承担地点、篇章和书籍式的识别作用。字体文件没有随包分发，中文字体缺失时会采用系统可用的回退字体，排版外观因此可能略有差异。

桌面首页保留左侧文字的呼吸空间，把三维主体放在右侧视区。阅读页则用真正的双栏书页组织信息：材料在左，回答在右，页码与保存动作退居次级。移动端不缩小一整张桌面书页，而是将阅读材料放在回答之前，保持正常字号、可滚动内容和可触及的按钮。

植物图版、备用庭院与五叶标记均为程序构造的 SVG。目标是印刷插图的秩序感，而不是把噪点、磨损和装饰纹样铺满每一块空间。纸面只有很轻的质感，墨色与纸色的可读性优先于“做旧”的程度。

## 空间与器物

庭院包含水面上的石台、开放式木构、宽檐屋盖、低墙、树冠、近景植被、悬灯和书桌。它们是实际的 Three.js 场景节点，不是把一张背景图做视差移动。备用 SVG 仅在不支持 WebGL、依赖缺失、渲染失败或用户选择静态模式时出现，不能被当作三维运行截图。

信匣是一只服务于学院通信的小型器物，而不是藏宝箱。箱体由独立的底板、四面箱壁、内衬和边条组成；顶部边条不会用实心板遮住内腔。箱盖以真实后缘铰链为旋转中心，开盖约 97 度。金属护条、铆钉、扣件与刻纹以材质和几何共同表达，尺寸统一在参数化模型中。

信封由纸背、左右折片、底折片、上翻盖、封蜡与内页组成。封蜡先脱离，翻盖再绕折线翻起，内页随后上升。纸张曲率直接更新顶点并重算法线，不是给整体平面施加统一的弯曲错觉。正面、背面、折痕和纸厚采用不同的深度位置，避免彼此共面。

进入问卷后，三维不再争夺注意力。环境时间停止推进，渲染循环在镜头稳定后暂停；只有窗口变化、画质设置或阶段变化才重新请求绘制。用户不需要一边写长文，一边承受持续的镜头漂移和水面运动。

## 交互编排

流程有七个明确阶段：抵达庭院、靠近信匣、取出信封、阅读邀请、书写问卷、核对来信和收到回执。阶段关系由独立状态机限制，不用任意长的定时器猜测用户已经走到了哪里。镜头动作可以被后续动作接续或被直接阅读替代。减少动态设置会跳过过渡，而不会改变表单与提交逻辑。

启封词由服务器验证。书写可以在不同页之间自由返回，每次输入都会尝试保存本机草稿；保存失败时界面会提示导出备份。导入草稿会过滤已移除题目、未知选项和危险键名，并限制字段长度。导入本身不授予服务端访问权限。

必答缺失会回到对应页并聚焦实际输入框，而不只在页面顶部显示一个笼统错误。客观问答由服务端核对，最终提交也会再次验证，不能通过前端跳页绕过。题库版本变化会要求重新启封，已经填写的本机草稿仍然保留。

提交必须经过核对与阅览授权。界面只在服务器返回持久化回执之后显示成功；相同答题凭据重试会返回同一份记录。断网、错误口令、过期凭据、停止收信和内容不完整都有对应的错误路径，不使用延时后自动显示成功的演示逻辑。

## 渲染实现

默认渲染器是 Three.js `0.180.0` 的 `WebGLRenderer`。采用普通 ES 模块，前端不依赖 React、Vue 或 Vite；后台保留原有 Node API，并增加新的启动、资源整理和测试脚本。锁定版本是为了让自定义材质与渲染管线有明确的接口基线，并非声称这是当前最新版本。首次安装通过 npm 获取 Three.js，随后将运行所需模块放到同源 `web/vendor`，运行中不需要请求 CDN。[4]

材质以 `MeshStandardMaterial` 为主，蜡封使用 `MeshPhysicalMaterial`。木纹、石纹、纸纤维与叶脉由固定种子的 Canvas 纹理生成；照明使用程序生成的环境贴图经过 PMREM 预过滤，再配合半球光、方向光和少量局部灯光。这里没有声称使用摄影测量材质、扫描资产或外部 HDRI。

树叶通过 `InstancedMesh` 批量绘制，顶点着色器提供轻微风动，深度材质使用同一形变，避免叶片与阴影脱节。静态建筑、箱壁与箱盖内部的静态装饰按材质合批，但盖板、封蜡和内页仍保持独立的动画节点。不同姿态的对象不会被错误烘焙到同一网格。

水面使用镜像相机、离屏渲染目标和裁切平面生成反射，每三帧更新一次反射纹理。片元着色器计算小幅波纹与雨滴涟漪，扰动采样并加入视角相关的反射权重。这是平面反射，不是屏幕空间反射、实时光线追踪或物理流体模拟。

细腻档使用自定义深度合成器：颜色与深度先写入离屏目标，再做轻量远景模糊、受控的亮部扩散、暗角和细微颗粒。支持浮点颜色附件时使用半浮点目标，否则降低为普通目标。最终通过 Three.js 的色调映射和颜色空间输出，而不是给所有材质重复做伽马校正。

## 质量分档与降级

轻盈档使用 650 片实例叶片，限制像素比为 1，关闭方向光阴影、平面反射与景深合成，但保留真实几何和水面着色。均衡档使用 1550 片叶片、1024 阴影图、384 反射目标和最高 1.35 像素比。细腻档仍使用 1550 片叶片，将阴影图提高到 2048、反射目标提高到 768、像素比上限提高到 1.8，并启用深度合成。三个档位的首页都会先展示静态 SVG，再按滚动进度逐步交给三维庭院。实际帧率没有在本次环境中测量，因此这些是实现参数，不是性能承诺。

窗口尺寸变化使用 ResizeObserver；页面隐藏时停止绘制并暂停音景；返回阅读页时不继续运行背景动画。WebGL 上下文丢失或着色器运行失败会交还静态庭院，不妨碍表单。退出三维模式时会释放几何、材质、纹理、反射目标、合成目标、阴影资源和渲染上下文。

音景在页面初始加载时保持静音，用户首次交互后自动开启，并可通过页首按钮随时关闭。它由 Web Audio 合成的低强度雨声与短促音阶组成，不下载音频文件。它是气氛辅助，不是判断交互成功的唯一反馈。

## 实现范围与验收边界

本次完成了新的玩家界面、三维场景代码、着色器、参数化模型、草稿逻辑、收信流程与同风格主持人档案室。后者能阅览真实来信、保存批注与状态、修改启封词、暂停收信，以及编辑、导入和导出题笺。后台仍是适合单个团务服务的单进程 JSON 持久化，不应直接多进程扩容或作为大型多租户平台使用。

源码静态检查、Node 单元与 API 测试，以及真实本地 API 驱动的浏览器交互已经执行。浏览器因环境策略运行在 about:blank 测试夹具中，页面资源由测试执行器转发；草稿存储使用内存替身。它不是正常地址栏导航、真实浏览器持久化或完整 CSP 兼容性测试。

当前工作环境无法从 npm 下载依赖，外部浏览器也不能把依赖下载为本地可用附件。因此 Three.js GPU 场景、WebGL 着色器实际编译、模型合批运行、真实帧率、GLB 导出与移动端 GPU 兼容性不在本次已验证范围。项目没有实现 GLB 导出，也没有将其列为交付能力。提供了安装后可执行的真实 Three.js 几何测试，以及可切换到正常 HTTP 导航的浏览器测试入口。

预览图中的庭院是静态回退插图；书页、题目、核对页和档案室则是实际前端 DOM 的运行截图。不能用这些图反向证明三维效果已经通过 GPU 验收。具体测试结果见 `TESTING.md` 与原始结果文件。
